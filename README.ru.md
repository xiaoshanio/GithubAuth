# Github Auth

Локальное зашифрованное хранилище аккаунтов GitHub, упакованное для Windows с помощью Tauri 2.

**Прочтите на других языках:** [简体中文](README.zh-CN.md) · [English](README.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · **Русский** · [Français](README.fr.md) · [Tiếng Việt](README.vi.md) · [한국어](README.ko.md)

## Языки интерфейса

Приложение поставляется с 13 языками интерфейса: 简体中文, 繁體中文, English, 日本語, 한국어, Русский, Français, Tiếng Việt, Español, Italiano, Português, Suomi и Filipino. При первом запуске интерфейс следует языку операционной системы; язык можно изменить в любой момент в настройках хранилища (Vault settings), и выбор запоминается.

## Требования

- Windows 10 или Windows 11
- Node.js и pnpm
- Rust stable с целевой платформой `x86_64-pc-windows-msvc`
- Microsoft C++ Build Tools
- Microsoft Edge WebView2 Runtime

## Разработка

```powershell
pnpm install
pnpm tauri:dev
```

## Сборка

```powershell
pnpm tauri:build
```

Результаты сборки:

- Переносимый исполняемый файл: `src-tauri/target/release/github-auth.exe`
- Установщик NSIS: `src-tauri/target/release/bundle/nsis/Github Auth_1.0.0_x64-setup.exe`

Установщик открывает селектор языка с английским и упрощённым китайским, а также использует LOGO приложения для установщика, деинсталлятора, исполняемого файла и ярлыков.

## Безопасность

- Формат хранилища v2 шифрует полезную нагрузку целиком с помощью случайного 256-битного ключа данных и AES-256-GCM.
- Мастер-пароль обрабатывается через Argon2id (64 МиБ, 3 итерации, параллелизм 1) со случайной солью. Производный ключ обёртывает ключ данных; он не шифрует записи аккаунтов напрямую.
- Каждая запись полезной нагрузки и каждая обёртка ключа пароля используют новый 96-битный AES-GCM nonce и аутентифицированные данные конкретного назначения.
- Конверты, полезные нагрузки, контейнеры резервных копий, ограничения KDF, идентификаторы записей и ссылки на группы проверяются серверной частью на Rust перед использованием.
- Файлы хранилища заменяются атомарно со сквозной записью (write-through) в Windows. Приложение работает в единственном экземпляре, чтобы предотвратить параллельную запись в хранилище.
- Файлы хранилища версии 1 с PBKDF2-SHA-256 переносятся на v2 только после того, как старый пароль успешно расшифрует и аутентифицирует полезную нагрузку целиком.
- Пароли, расшифрованные полезные нагрузки и ключи шифрования не записываются в журналы приложения. Конфиденциальные буферы Rust по возможности очищаются при освобождении.
- Конверт или резервная копия, которые превысили бы читаемый предел размера, отклоняются до записи чего-либо, поэтому чрезмерно большая полезная нагрузка никогда не сможет заменить исправный файл хранилища нечитаемым.
- URL-адреса аватаров, хранящиеся в хранилище, должны использовать источник `https` и ограничены по длине, как и все остальные поля аккаунта, прежде чем полезная нагрузка будет принята.
- Окно не имеет оформления, его рамка отрисовывается самим приложением. Веб-представлению выдано ровно пять оконных разрешений (`start-dragging`, `minimize`, `toggle-maximize`, `is-maximized`, `close`) с областью действия для окна `main`; никакие разрешения файловой системы, оболочки, путей или событий не предоставляются, а доступ к хранилищу остаётся за собственными командами приложения.

### Быстрая разблокировка через аутентификатор

Быстрая разблокировка через Google Authenticator использует стандартный TOTP из 6 цифр с интервалом 30 секунд. Секрет TOTP и ключ данных хранилища защищены Windows DPAPI для текущего пользователя Windows и привязаны к идентификатору хранилища. Успешные временные шаги не могут быть воспроизведены повторно, а повторные неудачи запускают экспоненциальную задержку (cooldown).

Быстрая разблокировка — это удобная функция, привязанная к устройству, а не переносимый второй пароль шифрования. Мастер-пароль всегда остаётся доступным и является единственным учётным данным, способным расшифровать резервную копию на другом устройстве. Привязка быстрой разблокировки никогда не включается в резервные копии.

## Зашифрованные резервные копии

- Ручные резервные копии используют формат `.ghauth-backup` и записываются через серверную часть на Rust.
- Автоматические резервные копии выполняются только пока Github Auth открыт, в том числе когда хранилище заблокировано. Поддерживаемые интервалы: 6 часов, 12 часов, ежедневно и еженедельно.
- Каталогом автоматических резервных копий по умолчанию является `%LOCALAPPDATA%\com.githubauth.vault\backups`; каталог и количество хранимых копий можно изменить в настройках хранилища.
- Резервная копия использует мастер-пароль, который был действителен на момент её создания. Смена текущего мастер-пароля не влияет на более старые резервные копии.
- Для импорта сначала требуется исходный пароль резервной копии. Добавление данных или размещение их в группе резервных копий с датой сохраняет текущие настройки хранилища.
- Замена текущих данных всегда требует текущего пароля хранилища в качестве отдельного шага авторизации. Пользователь может создать резервную копию, защищённую текущим паролем, перед заменой.
- Импортированные данные повторно шифруются с использованием ключа данных текущего хранилища и текущей обёртки мастер-пароля. Импорт никогда не меняет текущий пароль или привязку аутентификатора.

Зашифрованный конверт хранится в `%LOCALAPPDATA%\com.githubauth.vault`. Сборки для производства исключают прежнюю среду выполнения Manus, сборщик отладки и прокси хранилища.

Запустите тесты безопасности с помощью:

```powershell
pnpm test:security
cargo test --manifest-path src-tauri/Cargo.toml
```

Выпускные сборки остаются неподписанными, пока не будет настроен сертификат подписи кода Windows. Неподписанные установщики могут вызывать предупреждения Microsoft Defender SmartScreen.
