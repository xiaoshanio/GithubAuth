# Github Auth

Tauri 2 でパッケージ化された、Windows 向けのローカル暗号化 GitHub アカウント vault。

**他の言語で読む:** [简体中文](README.zh-CN.md) · [English](README.md) · [繁體中文](README.zh-TW.md) · **日本語** · [Русский](README.ru.md) · [Français](README.fr.md) · [Tiếng Việt](README.vi.md) · [한국어](README.ko.md)

## インターフェース言語

アプリには 13 のインターフェース言語が搭載されています：简体中文、繁體中文、English、日本語、한국어、Русский、Français、Tiếng Việt、Español、Italiano、Português、Suomi、Filipino。初回起動時はオペレーティングシステムの言語に従います。言語は Vault の設定からいつでも変更でき、選択内容は記憶されます。

## 必要要件

- Windows 10 または Windows 11
- Node.js と pnpm
- `x86_64-pc-windows-msvc` ターゲットを含む Rust stable
- Microsoft C++ Build Tools
- Microsoft Edge WebView2 Runtime

## 開発

```powershell
pnpm install
pnpm tauri:dev
```

## ビルド

```powershell
pnpm tauri:build
```

ビルド成果物：

- ポータブル実行ファイル：`src-tauri/target/release/github-auth.exe`
- NSIS インストーラー：`src-tauri/target/release/bundle/nsis/Github Auth_1.0.0_x64-setup.exe`

インストーラーは英語と简体中文の言語セレクターを表示し、インストーラー、アンインストーラー、実行ファイル、ショートカットのすべてにアプリケーションの LOGO を使用します。

## セキュリティ

- Vault フォーマット v2 は、ランダムな 256 ビットのデータキーと AES-256-GCM でペイロード全体を暗号化します。
- マスターパスワードは、ランダムなソルトとともに Argon2id（64 MiB、3 回の反復、並列度 1）で処理されます。導出されたキーはデータキーをラップするためのもので、アカウントレコードを直接暗号化するものではありません。
- ペイロードの書き込みおよびパスワードキーのラップのたびに、新規の 96 ビット AES-GCM nonce と用途固有の認証データが使用されます。
- エンベロープ、ペイロード、バックアップコンテナ、KDF 制限、レコード ID、グループ参照は、使用前に Rust バックエンドによって検証されます。
- Windows では、Vault ファイルは write-through セマンティクスでアトミックに置き換えられます。アプリケーションはシングルインスタンスで動作し、Vault への同時書き込みを防ぎます。
- バージョン 1 の PBKDF2-SHA-256 Vault ファイルは、旧パスワードがペイロード全体の復号と認証に成功した場合にのみ v2 へ移行されます。
- パスワード、復号されたペイロード、暗号化キーはアプリケーションのログに書き込まれません。実用上可能な範囲で、機密性の高い Rust バッファはドロップ時にクリアされます。
- 読み取り可能なサイズ制限を超えるエンベロープやバックアップは、何かが書き込まれる前に拒否されます。そのため、過大なペイロードが正常な Vault ファイルを読み取り不可能なファイルで置き換えることは決してありません。
- Vault に保存されるアバター URL は `https` オリジンでなければならず、他のすべてのアカウントフィールドと同様に長さ制限が課された後でなければペイロードとして受け入れられません。
- ウィンドウは装飾なしで、その外観はアプリケーションが描画します。Webview には `main` ウィンドウにスコープされた 5 つのウィンドウ権限（`start-dragging`、`minimize`、`toggle-maximize`、`is-maximized`、`close`）のみが付与され、ファイルシステム、シェル、パス、イベントの権限は一切公開されません。Vault へのアクセスは常にアプリケーション自身のコマンドの背後にあります。

### Authenticator クイックアンロック

Google Authenticator クイックアンロックは、標準的な 6 桁・30 秒周期の TOTP を使用します。TOTP シークレットと Vault データキーは、現在の Windows ユーザーに対して Windows DPAPI によって保護され、Vault ID にバインドされます。成功した時間ステップはリプレイできず、繰り返し失敗すると指数関数的なクールダウンが発生します。

クイックアンロックはデバイスにバインドされた利便性機能であり、持ち運び可能な第二の暗号化パスワードではありません。マスターパスワードは常に利用可能であり、別のデバイスでバックアップを復号できる唯一の資格情報です。クイックアンロックのバインディングがバックアップに含まれることはありません。

## 暗号化バックアップ

- 手動バックアップは `.ghauth-backup` 形式を使用し、Rust バックエンドを通じて書き込まれます。
- 自動バックアップは、Vault がロック中である場合を含め、Github Auth が開いている間にのみ実行されます。対応する間隔は 6 時間、12 時間、毎日、毎週です。
- 自動バックアップの既定ディレクトリは `%LOCALAPPDATA%\com.githubauth.vault\backups` です。ディレクトリと保持数は Vault の設定で変更できます。
- バックアップには、そのバックアップが作成された時点で有効だったマスターパスワードが使用されます。現在のマスターパスワードを変更しても、以前のバックアップは変わりません。
- インポートにはまず、そのバックアップの元のパスワードが必要です。データの追加や日付付きバックアップグループへの配置では、現在の Vault 設定が保持されます。
- 現在のデータの置き換えには、常に別個の承認ステップとして現在の Vault パスワードが必要です。ユーザーは置き換えの前に、現在のパスワードで保護されたバックアップを作成できます。
- インポートされたデータは、現在の Vault のデータキーと現在のマスターパスワードラッパーで再暗号化されます。インポートによって現在のパスワードや Authenticator のバインディングが変更されることはありません。

暗号化されたエンベロープは `%LOCALAPPDATA%\com.githubauth.vault` の下に保存されます。プロダクションビルドでは、以前の Manus ランタイム、デバッグコレクター、ストレージプロキシは除外されています。

セキュリティテストの実行：

```powershell
pnpm test:security
cargo test --manifest-path src-tauri/Cargo.toml
```

Windows のコード署名証明書が設定されるまで、リリースビルドは署名されません。署名のないインストーラーは、Microsoft Defender SmartScreen の警告を引き起こす可能性があります。
